# 自适应产品维度

把这套框架当作一张决策地图，不要当成必须依次填满的五步流程。它要能处理软件、AI、硬件、服务、内容、平台、企业产品和线下体验。

所有项目都先回答需求、价值和负向边界。其他维度和横向约束，只有在会改变产品决定时才展开，并明确哪些内容本次有意跳过。

## 先判断产品靠什么交付价值

| 产品类型 | 通常重点检查 | 需要时再补充 |
|---|---|---|
| 软件或 App | 需求与价值、产品系统、使用过程、触点 | 数据、隐私、无障碍、分发、支持 |
| AI 产品 | 模型带来的新机制、交互与纠错、信任 | 数据权利、不确定性、人工监督、评测、成本 |
| 硬件或实体产品 | 产品系统、拥有与使用周期、物理形态 | 制造、供应、安全、维修、包装、零售 |
| 服务产品 | 服务旅程、人员与运营、异常恢复 | 产能、培训、话术、场地、政策、单位经济 |
| 内容或社区 | 内容系统、参与过程、创作者与用户价值 | 推荐、治理、激励、审核、申诉 |
| 平台或交易市场 | 多方价值、规则与激励、交易过程 | 冷启动、流动性、信任、纠纷、合规 |
| 企业产品 | 多角色价值、工作流、系统适配、采用过程 | 采购、权限、集成、迁移、管理后台 |
| 线下空间或活动 | 空间和服务旅程、实体触点 | 容量、人员、安全、无障碍、天气、物流 |

一个产品可以同时属于几种类型，不要为了分类而分类。

## 决策依赖

`负向边界 → 需求与价值 → 产品机制与系统边界 → 使用与交付 → 触点与形态 → 体验与信任 → 验收条件`

这是依赖关系，不是瀑布流程。下游发现矛盾时，回到最早出错的决定，再把变化传递下来。

## 1. 需求与价值

这个维度始终要做。

重点回答：

- 谁在什么处境下遇到了问题？谁使用、谁购买、谁受益、谁交付？
- 用户真正想取得什么进展、结果、缓解或身份认同？
- 现在的替代方案是什么，它为什么还凑合能用？
- 各方创造、得到、支付或承担了什么价值和成本？
- 为什么是现在？什么可观察的结果能证明这次下注成立？

至少形成：目标与排除用户、具体场景、未满足需求、当前替代、换用阻力、产品承诺、价值交换、成功信号和最低成本验证。

当产品不依赖功能清单也能被说清楚时，才算暂时通过。

## 2. 产品系统

当产品由能力、内容、数据、硬件、服务、人员、合作方或规则共同组成时，检查这个维度。

重点回答：

- 能兑现承诺的最小完整机制是什么？
- 哪些组件和能力不可缺，哪些只是行业惯例？
- 产品从哪里开始、在哪里结束？用户、员工、合作方和外部系统各负责什么？
- 哪些规则、成本、依赖和质量底线维持系统运转？

明确产品机制、系统边界、组成部分、责任划分、`必须做 / 以后做 / 不做`、关键规则和验收边界。

## 3. 使用与交付

只要价值需要经过发现、购买、准备、使用、履约、维护、支持、续费、退换或退出，就要检查完整生命周期。

重点回答：

- 产品怎样到达用户手里并进入可用状态？
- 用户、员工、系统、供应商和合作方在每一步做什么？
- 哪里会失败、等待、中断、交接、升级或恢复？
- 核心价值发生前后，还有哪些不可缺的环节？
- 团队靠什么运营能力反复兑现承诺？

形成用户旅程、服务流程、运营流程或拥有周期，以及状态、交接、异常、恢复、支持和退出规则。

## 4. 触点与形态

触点不只包括屏幕，也包括 API、AI 对话、设备、实体控制、包装、门店、空间、服务人员、通知、渠道和品牌沟通。

重点回答：

- 每个决定、动作和信息最适合出现在哪个触点？
- 什么必须可见、可触、就近、持续存在或逐步出现？
- 哪种形态最符合用户处境、环境和实现约束？
- 用户怎样知道现在是什么状态，下一步该做什么？
- 哪些惯例应该保留，哪里需要形成差异？

低保真原型只用于解决产品问题，不要在上游规则不清楚时用漂亮界面掩盖它。

如果是以界面为中心的数字产品，可以把经典五层作为嵌套工具：战略对应需求与价值，范围对应产品系统，结构对应使用关系，框架对应界面安排，表现对应体验表达。不要把它强加给以实体、运营、服务或商业系统为主的产品。

## 5. 体验与信任

当理解、情绪、安全、口碑和长期使用会影响产品成败时，检查这个维度。

重点回答：

- 用户在目标场景里应该感到什么？
- 哪些视觉、语言、材料、行为或人员信号能说明状态与质量？
- 用户行动前必须理解和相信什么？
- 产品在等待、不确定、失败、恢复和退出时如何表现？
- 哪些表达会破坏负向边界或产品气质？

形成产品气质、信任原则、反馈方式、预期管理、恢复语言，以及无障碍、包容、隐私和感官约束。

## 横向约束

只检查会改变决定的部分：

- **商业与经济**：定价、成本结构、激励、收入、现金周期、可持续性。
- **技术、数据与 AI**：可行性、架构、模型行为、数据权利、评测、不确定性、人工监督。
- **运营与供应**：人员、制造、采购、质量、产能、物流、维护。
- **安全、法律与治理**：人身安全、隐私、安全性、无障碍、监管、审核、问责。
- **分发与采用**：渠道、销售、上手、迁移、换用成本、教育、生态合作。
- **环境与生命周期**：耐用、维修、能耗、材料、回收、长期支持。

不要把这些写成通用章节。只需说清它改变了哪个决定，并由此产生什么验收边界。
